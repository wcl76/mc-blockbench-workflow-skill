# 运行时约定与资产验收

在确定当前资产的工程格式、规划动画、导出或验证时读取。适用于生物、家具、机器、方块、道具与装备；只启用相关检查，不把某种模组的特殊要求变成通用规则。

## 建模前确认接收方

平台决定运行环境，接收模型的具体模组、插件或渲染／动画库决定资源契约。不能只按 Java／基岩版选择格式，也不默认所有 Java 动画资产都使用 GeckoLib。

优先读取已有项目配置、示例资产与对应版本官方文档，记录以下最低信息：

| 项目 | 本次需要记录 |
| --- | --- |
| 接收方 | MC 版本、加载器（适用时）、具体模组／资源包／附加包、渲染与动画库版本 |
| 资产用途 | 世界中的方块／实体、手持道具、玩家装备、组合模块等 |
| 工程与导出 | 模板、允许的几何／旋转／UV、导出 codec 和格式版本 |
| 尺度与朝向 | 单位、原点、朝向、与玩家／方块或连接资产的比例 |
| 标识与结构 | 命名空间、几何标识、骨骼／挂接节点、动作名与必要父子关系 |
| 资源引用 | 模型、纹理、动画、显示配置的文件名与游戏内引用路径 |
| 功能依赖 | 静态或可动、触发条件、所需组件／控制器／代码接入 |

未知接收方时可完成概念与结构设计；要新建工程或承诺游戏兼容前，先确定影响它的格式要求。普通装饰物不必设计骨骼动作，静态方块不必采用实体动画路线。已有模组提供模板时优先兼容模板；不能为了统一目录或命名而破坏程序识别。

对于陌生工具链，建议先用当前资产的粗模验证一次最小导出／加载，再投入大量细节；仅在用户请求接入且环境允许时执行游戏侧操作，否则交付待验证的具体契约，不擅自扩展为完整模组开发。

## 按资产用途选择检查

| 资产用途 | 编辑器与游戏内需要关注的内容 |
| --- | --- |
| 生物／NPC | 游戏比例、关节与接地、动作穿插、行走与攻击组合、触发与切换；涉及命中时核对实体碰撞定义 |
| 家具／可交互装饰 | 放置朝向、玩家尺度、门／抽屉开合、运动后露出表面；适用时核对碰撞、选择及坐席等交互位置 |
| 机器／连接模块 | 接口尺寸／朝向、连接组合、活动间隙、工作／停止等状态表现与触发、共享模块兼容 |
| 静态／建筑方块 | 几何边界、相邻方块拼接与纹理平铺、旋转变体、面剔除、碰撞与选择范围 |
| 道具／手持物品 | 第一／第三人称左右手、GUI、掉落与展示框等适用视角；不把预览相机角度当成已导出的显示设置 |
| 护甲／穿戴装备 | 对应玩家／实体模板、指定骨骼、各部位贴合、抬手／行走等姿态、穿透与挂接 |
| 武器／可换组件 | 在手持检查基础上核对配件接口、必要定位节点和动作；特殊节点名以目标框架为准 |

一个资产可能属于多个用途，例如可开门的家具方块需同时检查方块与家具项。将不适用项标明不适用，不要求每件资产制作所有视角、状态或动画。碰撞、行为及动作触发通常需要游戏侧定义，不把“模型看起来正确”当作这些功能已经完成。

## 动画先规划播放关系

建关键帧前写简短动作表：

| 动作 ID | 触发／结束条件 | 循环或单次 | 驱动部件 | 过渡／叠加关系 | 音效／粒子／事件 | 来源 |
| --- | --- | --- | --- | --- | --- | --- |
| 按目标契约命名 | 游戏状态或用户操作 | 含结束保持策略 | 骨骼范围 | 回到哪个姿态、能否与其他动作同时播 | 所需时间点及绑定位置 | 新制作／复用／框架默认 |

只制作用户需要的动作，同时核对框架最低要求：缺少必需动作时优先使用已允许的模板／默认动作或说明新增需求；不交付明知不能加载的动画集。区分静止姿态、循环动作和一次性事件；检查首尾、状态切换、打断／重复触发、多个动作驱动同一骨骼的冲突，以及活动件隐藏／显示后的状态。

编辑器里能播放不代表游戏会触发。导出后仍需正确引用、控制器或接入代码；音效／粒子关键帧也需要运行时支持和处理。检查点预览不得冒充游戏侧验证，不强制所有项目自写状态机。

## 材质、显示与优化验收

- 外观以项目选定风格为准。原版融合风格优先简洁轮廓与合理像素比例；精细像素或其他风格使用自己的预算，不统一规定 cube 数、贴图尺寸或禁止细小结构。
- 检查共面闪烁、非预期重复面、纹理错属，以及游戏需要的透明／半透明／双面／发光表现。编辑器材质设置不必然等同于目标运行时。
- 删除隐藏面前保存检查点，只处理所有相关动作、组合和可见视角下都不会露出的面。自动优化后复查活动件与内壁；无法证明安全时保留。
- 根据实际观看距离、同屏数量和运行时能力决定是否需要低精度版本／LOD 或独立物品图标。不是所有资产都需要，也不能只生成文件就声称 LOD 切换已经接入。
- 检查实际尺寸下的可读性，不能只放大截图评估。方块材质按需检查相邻重复，手持／穿戴资产与玩家参考对照，组合件与真实接口对照。

## 导出与验收记录

保留可编辑工程和独立源资产；按接收方要求分别导出模型、纹理、动画及显示配置等实际需要的资源。检查资源标识与文件引用，清理不应导出的参考平面、辅助体块和临时测试动作；可保留其源工程记录。

逐级记录证据与结果：结构／贴图检查、编辑器预览、导出重新读取、游戏内加载与用途检查。未执行的层级记为待验证；重新读取通过不等同于游戏兼容。游戏侧检查按资产选择加载报错、比例／视角、材质／剔除、碰撞／交互、动作切换与模块组合，不一律要求全部项目。

## 调研依据

以下资料用于支持上述通用原则，示例参数只适用于对应版本与工具链；实际执行时查阅目标版本文档，不照搬特定教程的数值或专用名字。该检查体系是本工作流的整理，不是这些项目共同发布的标准。

- [Blockbench Minecraft 风格指南](https://blockbench.net/wiki/guides/minecraft-style-guide/)：简洁形状、像素比例、材质表达与方块平铺；其原版风格原则不是所有风格的硬限制。
- [Blockbench 使用概览](https://blockbench.net/wiki/guides/blockbench-overview-tips/)：Display Mode、不同显示场景与骨骼／动画编辑。
- [微软实体建模与动画教程](https://learn.microsoft.com/en-us/minecraft/creator/documents/entitymodelingandanimation?view=minecraft-bedrock-stable)：骨骼层级、动作触发与实体资源接入。
- [微软方块渲染与光照教程](https://learn.microsoft.com/en-us/minecraft/creator/documents/customblockrenderlighting?view=minecraft-bedrock-stable)、[碰撞组件参考](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/examples/blockcomponents/minecraftblock_collision_box?view=minecraft-bedrock-stable)：材质渲染及与模型外观分开的碰撞定义。
- [GeckoLib 插件使用](https://wiki.geckolib.com/docs/geckolib5/making-models/blockbench-plugin-usage/)、[控制器](https://wiki.geckolib.com/docs/geckolib5/concepts/animation/controller/overview/)、[导出](https://wiki.geckolib.com/docs/geckolib5/making-models/exporting-the-files/)、[资源目录](https://wiki.geckolib.com/docs/geckolib5/making-models/placing-the-files/)：类型模板、播放关系及按版本导出／引用。
- [TaCZ 特殊组名](https://tacwiki.mcma.club/zh/gunpack/gun/03_sp_group_name.html)、[低精度模型](https://tacwiki.mcma.club/zh/gunpack/gun/06_lod.html)：说明具体框架会有专用节点与显示优化要求，仅在该框架适用。
