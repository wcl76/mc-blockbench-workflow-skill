# 交付与阶段记录

新项目按 [模型清单、联动与命名](asset-catalog-naming.md) 在 `project/` 保存项目汇总、模型清单、联动与阶段记录；已有项目保持原记录入口。小改动更新已有文档，不创建冗余文件。主题确定后可在制作当前资产的同时逐步补充规划。

首次创建项目时先按 [项目访谈与需求汇总](project-intake.md) 保存项目设计简报，字段标明已确认/建议/待定；续做或需求变化时同步更新。接入过程记录插件、服务、客户端各自状态和剩余操作，未实际验收不能写为已连接。安装路径仅在本地接入需要时记录，公开交付使用可移植说明，不包含凭据或无关客户端配置。

记录以下内容：

- 资产目标：版本、平台、具体接收模组／工具链、加载器、格式与模板、渲染/动画库及版本、风格、尺度与用途、所需动作与播放关系。
- 工具能力：所用 MCP 实现/版本（能读取时）、实际可用操作、缺失能力、图像生成入口与实际模型选择证据。
- 设计决策：选定概念图的路径与版本、部件材质表、参考到元素／UV 的对应、部件运动表（父级、轴心、方向、间隙、配件接口）、外观对照与极限姿态检查结果、未决差异及有依据的取舍；比例、视图矛盾如何解决、坐标系、朝向、纹理尺寸、复杂度取舍。
- 当前进度：设计、概念图、几何、UV、贴图、动画、导出、代码接入、游戏验证分别为完成/进行中/未开始/不适用；附验证证据路径及未解决问题。
- 模型清单与联动：当前范围与后续计划、主题对应、可替换／连接／同步运动／共享关系、接口契约和验证状态；每次新增或修改资产同步受影响记录。
- 用途验收：按 [运行时约定与资产验收](runtime-asset-validation.md) 记录适用视角、比例、材质／剔除、碰撞／交互、动作触发／切换与模型联动；区分编辑器、重新导入、游戏验证及不适用项。
- 文件清单：可编辑工程、参考图、几何规格、纹理、动画与导出文件，以及相关模组资源路径。
- 下一步：恢复任务应读取的工程和记录，剩余任务及其依赖。

文件布局按命名参考：新项目使用 `project/`、`concepts/<category-id>/<series-id>/<asset-id>/` 与 `models/<category-id>/<series-id>/<asset-id>/`，无系列时省略系列层。已有项目沿用其惯例并记录路径对应，不迁移现有 `assets/<asset-id>/` 等目录。只按实际产出建立子目录，联动关系引用稳定模型 ID，共享部件保存唯一源资产。

一次简单流程验证建议选择结构清楚的小型资产，检查“保存 → 重新读取 → UV/贴图检查 → 导出 → 目标运行时显示”。只有实际执行的部分能写为已验证。用户只请求设计方案时，到设计交付即结束，不擅自扩展为完整模组开发。
