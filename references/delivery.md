# 交付与阶段记录

在任务目录维护简短的 `asset-status.md`；小改动可更新已有记录，不必创建冗余文件。

记录以下内容：

- 资产目标：版本、平台、加载器、格式、渲染/动画库、风格、尺寸、所需动作。
- 工具能力：所用 MCP 实现/版本（能读取时）、实际可用操作、缺失能力、图像生成入口与实际模型选择证据。
- 设计决策：采用的参考图、比例、视图矛盾如何解决、坐标系、朝向、纹理尺寸、复杂度取舍。
- 当前进度：设计、概念图、几何、UV、贴图、动画、导出、代码接入、游戏验证分别为完成/进行中/未开始/不适用；附验证证据路径及未解决问题。
- 文件清单：可编辑工程、参考图、几何规格、纹理、动画与导出文件，以及相关模组资源路径。
- 下一步：恢复任务应读取的工程和记录，剩余任务及其依赖。

文件布局按现有项目惯例；独立资产可使用 `assets/<asset-id>/`，将参考、工程、纹理、导出与验证截图放在相应子目录，按实际产出建立目录。

一次简单流程验证建议选择结构清楚的小型资产，检查“保存 → 重新读取 → UV/贴图检查 → 导出 → 目标运行时显示”。只有实际执行的部分能写为已验证。用户只请求设计方案时，到设计交付即结束，不擅自扩展为完整模组开发。
